# Opal resolves rubric-relative truth, not absolute truth

Opal is an optimistic oracle, but the "truth" it resolves is defined by each assertion's **Resolution Spec** — the immutable, time-independent asserter-supplied rubric (sources and their priority, definitions, and ambiguity handling), stored off-chain on Arweave with its canonical `ar://` URI onchain per [ADR-0015](0015-canonical-resolution-spec-uri.md). The LLM resolver and the voters **apply that spec**; they do not adjudicate any universal reality. The same statement text can therefore resolve differently across assertions. Evidence timing follows the protocol-wide current-information rule in [ADR-0013](0013-protocol-time-evidence.md), not an asserter-selected cutoff inside the spec.

**Why.** Real-world statements have no single objective verifier ("postponed" by whose definition, as of when?). Forcing the asserter to declare the resolution criteria turns an unbounded question ("is this true?") into a bounded, adjudicable one ("does this spec, correctly applied, yield True?"), and lets one oracle serve many use cases with different standards.

**Consequences.** The Resolution Spec is the most important artifact after the statement itself, so it must stay retrievable and integrity-checkable for the whole lifecycle (hence Arweave + canonical onchain URI). Once the Assertion transaction is accepted, the statement, Resolution Spec URI, Participant Bond, and deadlines are immutable. The asserter cannot edit or cancel the Assertion or withdraw its bond early; correcting a mistake requires a new Assertion while the original continues to resolution. Opal permits multiple Assertions with identical statement and spec content. Each has a unique identity, bond, windows, lifecycle, and outcome; the protocol never marks one as the canonical or latest replacement. Disputes and votes are framed as "applying this spec to the latest authoritative information available now, the answer is X," not "in reality it's X." Garbage-spec-in → garbage-truth-out, faithfully applied; vetting the spec is the integrator's responsibility (an integrator must read the spec before trusting an outcome). See also [ADR-0007](0007-unresolvable-vs-no-consensus.md), [ADR-0013](0013-protocol-time-evidence.md), and [ADR-0015](0015-canonical-resolution-spec-uri.md).
