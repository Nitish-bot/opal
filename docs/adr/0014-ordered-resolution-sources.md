# Require ordered authoritative sources and deterministic conflict rules

Every Resolution Spec identifies its authoritative sources in priority order and defines how conflicts are resolved. A spec with one authoritative source satisfies the ordering requirement automatically. A multi-source spec must state which source controls when current information conflicts and whether a lower-ranked source may substitute when a higher-ranked source is unavailable. If the declared hierarchy and rules do not settle a material conflict or availability gap, the Assertion resolves `Unresolvable`; the resolver and voters cannot invent an unstated preference.

**Why.** Listing several nominally authoritative sources without precedence lets each actor choose the source supporting their preferred answer. That converts rubric-relative truth into discretionary source shopping and makes the same unchanged spec yield incompatible but superficially valid interpretations. A deterministic hierarchy keeps the spec bounded while the protocol-wide evidence-timing rule in [ADR-0013](0013-protocol-time-evidence.md) ensures each layer reads the latest available version of those sources.

**Consequences.** Creating clients and integration services must reject a multi-source spec whose source order, conflict rule, or unavailability behavior is missing or ambiguous. The onchain program cannot inspect off-chain content, so a bypassing client can still create an Assertion with a malformed spec; the LLM resolver and voters must then select `Unresolvable` rather than silently supplying missing policy. Source order does not freeze evidence, select a historical cutoff, or permit the spec to exclude later corrections. Integrators must read and accept the hierarchy before depending on an outcome.
